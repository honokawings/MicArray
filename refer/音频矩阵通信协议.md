# 音频矩阵通信协议

> 来源：`音频矩阵通信协议_260616.docx`
> 内容：自适应降噪麦克风阵列定向拾音设备的软件通信框架、PL/PS 通信协议、上位机/PS 通信协议及各类数据帧格式。

## 1. 软件通信框架

自适应降噪麦克风阵列定向拾音设备软件主要由以下部分构成：

- FPGA
- ARM 控制端（PS）
- 上位机软件

软件通信结构如下：

```mermaid
flowchart LR
    PL[PL / FPGA] <-->|DMA + GPIO| PS[PS / ARM]
    PS <-->|TCP| HOST[上位机]
```

PS 作为服务端，只支持单个 client 终端连接。

### 1.1 字节序约定

除特别说明的业务 payload 外，帧协议中的所有多字节字段均按小端序传输和解析。

- 帧头语义值 `0x7e7e` 在线路中为 `7e 7e`。
- 帧类型 `0xee11` 在线路中为 `11 ee`。
- 音频帧长度 `38400` 在线路中为 `00 96 00 00`。
- 时间戳字段按 32 bit 小端序传输。
- 控制帧在线路上保留 8 路 `int16` 字段并按 16 bit 小端序传输；上位机只提供接口 0-5，字段 6-7 固定填零。
- 音频帧、心跳帧、控制帧帧尾语义值 `0x0d0a` 在线路中为 `0a 0d`。
- 视频帧帧尾固定为两个字节：第一个字节为 `0a`，第二个字节可为任意 `0x00~0xff` 值但必须存在。

### 1.2 服务端 TCP 通信参数

| 连接方式 | IP 地址 | 端口 |
|---|---:|---:|
| 有线 | `192.168.2.10` | `9968` |
| 无线 | `192.168.5.1` | `9968` |

## 2. PL 和 PS 通信设计

PL 和 PS 之间采用 `AXI-DMA` 进行通信，每次通信约定固定传输 `208` 字节数据。

每次通信帧头前 `16` 字节为通信头，用作通信数据处理参数；后续字节为实际数据。

### 2.1 PL/PS 通信帧格式

| 字节顺序 | 定义 | 说明 |
|---:|---|---|
| `0~1` | 帧头 | `0xaabb` |
| `2~3` | 帧类型 | `0xeeff` |
| `4~7` | 帧长度 | 数据区有效数据字节数 |
| `8~16` | 预留 | `-` |
| `16~208` | 数据区 | 通信有效数据，单帧不足 `208` 字节部分补 `0` |

> 注：原文表格中 `8~16` 与 `16~208` 在字节 `16` 处存在边界重叠；此处按原文保留。

## 3. 上位机和 PS 通信设计

上位机和设备建立通信连接以后，设备将获取的数据实时上传给上位机。

## 4. 音频数据帧格式

单帧为 FPGA 上传的单帧数据。

| 字节顺序 | 定义 | 说明 |
|---:|---|---|
| `0~1` | 帧头 | `0x7e7e` |
| `2~3` | 帧类型 | `0xee11` |
| `4~7` | 帧长度 | 数据区有效数据字节数 |
| `8~11` | 时间戳 s | 秒级时间戳 |
| `12~15` | 时间戳 us | 微秒级时间戳 |
| `16~n` | 数据区 | 音频数据，固定 `38400` 字节 |
| `n+1~n+2` | 帧尾 | `0x0d0a` |

音频数据区：

- 每个 TCP 音频帧包含 `200` 个采样点。
- 每个采样点包含 `48` 个通道。
- 每通道样本为 `32 bit` 小端数据。
- 数据排列方式为：采样点 0 的通道 0、通道 1、...、通道 47，随后采样点 1 的通道 0、通道 1、...、通道 47，依次到采样点 199。
- TCP 音频帧数据区总长度为 `48 * 4 * 200 = 38400` 字节，即 `0x9600`。

## 5. 视频数据帧格式

单帧数据为一帧完整的图像数据。

| 字节顺序 | 定义 | 说明 |
|---:|---|---|
| `0~1` | 帧头 | `0x7e7e` |
| `2~3` | 帧类型 | `0xee22` |
| `4~7` | 帧长度 | 数据区有效数据字节数 |
| `8~11` | 时间戳 s | 秒级时间戳 |
| `12~15` | 时间戳 us | 微秒级时间戳 |
| `16~n` | 数据区 | 视频数据 |
| `n+1` | 帧尾第一个字节 | 固定 `0x0a` |
| `n+2` | 帧尾第二个字节 | `0x00~0xff` 任意值，必须存在 |

视频帧总长度为 `16 + payloadLength + 2` 字节。解析器只校验第一个尾字节为 `0x0a`，但必须在收到第二个尾字节后才提交帧；第二个尾字节作为原始帧尾的一部分保留。

## 6. 上位机心跳帧

上位机每秒发送心跳帧，用于设备检测通信连接是否正常。

| 字节顺序 | 定义 | 说明 |
|---:|---|---|
| `0~1` | 帧头 | `0x7e7e` |
| `2~3` | 帧类型 | `0xcc00` |
| `4~7` | 帧长度 | `0x00` |
| `8~9` | 帧尾 | `0x0d0a` |

## 7. 上位机控制帧格式

上位机控制帧在线路上保留 8 个字段，通过 BRAM 前 `16` 字节和 PL 进行控制交互。业务层只暴露接口 0-5；最后两个字段不作为接口显示或参与控制逻辑，编码时固定填零，以保持 26 字节线协议兼容。

| 字节顺序 | 定义 | 说明 |
|---:|---|---|
| `0~1` | 帧头 | `0x7e7e` |
| `2~3` | 帧类型 | `0xcc11` |
| `4~7` | 帧长度 | `0x16` |
| `8~9` | 控制接口 0 | `16bit` 有符号控制值 |
| `10~11` | 控制接口 1 | `16bit` 有符号控制值 |
| `12~13` | 控制接口 2 | `16bit` 有符号控制值 |
| `14~15` | 控制接口 3 | `16bit` 有符号控制值 |
| `16~17` | 控制接口 4 | `16bit` 有符号控制值 |
| `18~19` | 控制接口 5 | `16bit` 有符号控制值 |
| `20~21` | 保留字段 6 | 上位机固定写入 `0x0000` |
| `22~23` | 保留字段 7 | 上位机固定写入 `0x0000` |
| `24~25` | 帧尾 | `0x0d0a` |

## 8. 帧类型汇总

| 帧类型 | 方向 / 用途 | 说明 |
|---:|---|---|
| `0xeeff` | PL ↔ PS | PL/PS 固定 208 字节通信帧 |
| `0xee11` | FPGA/设备 → 上位机 | 音频数据帧 |
| `0xee22` | 设备 → 上位机 | 视频数据帧 |
| `0xcc00` | 上位机 → 设备 | 心跳帧，每秒发送 |
| `0xcc11` | 上位机 → 设备/PL | 控制帧，通过 BRAM 前 16 字节与 PL 交互 |

## 9. 固定帧标识汇总

| 字段 | 数值 |
|---|---:|
| 上位机/PS 通信帧头 | `0x7e7e` |
| 上位机/PS 通信帧尾 | `0x0d0a` |
| PL/PS 通信帧头 | `0xaabb` |
| PL/PS 通信帧类型 | `0xeeff` |
| TCP 服务端端口 | `9968` |
| PL/PS 固定传输长度 | `208` 字节 |

## 10. 补充细节
- TCP协议帧均为小端序，包括帧头帧尾，帧类型和音视频数据
- 音频数据排列方式为：通道0-32bit，通道1-32bit，...，通道47-32bit，且为小端序排列
- TCP音频帧数据共38400字节（0x9600），单次传输共有200个采样点的音频数据

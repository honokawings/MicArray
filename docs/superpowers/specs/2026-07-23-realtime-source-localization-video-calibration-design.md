# 实时声源定位与视频四点校准设计

## 1. 背景与目标

MicArray 已具备实时 48 通道音频处理、实时视频解码、离线 WAV 声源定位、静态照片方向投影和源码级算法注册能力。本功能新增独立的“声源定位”页面，把实时视频与实时阵列音频组合起来，在视频上显示声源方向，并提供真实空间响应热力图、纯标记显示和便捷的四点视频校准。

目标如下：

- 复用实时视频解码结果，不重复解码或占用第二条设备连接。
- 复用现有 `ISoundSourceLocator`、GCC-PHAT、阵列几何和方向投影定义。
- 使用增益处理后的 48 通道实时音频持续分析一个主声源方向。
- 提供真实 SRP-PHAT 空间响应热力图和纯标记两种显示方式。
- 通过四次“稳定声源方向与视频点击点”采集，自动拟合视频视角参数。
- 显示并允许手动调整与离线音频分析页一致的五个物理视角参数。
- 校准与显示配置自动保存到本地，下次启动自动载入。
- 定位计算运行在独立线程，不阻塞音频播放、录音、视频、控制或 UI。
- 保持 Qt 6.5、C++20、Qt Widgets、MinGW 和 Ninja 兼容，不增加第三方运行时依赖。

## 2. 范围与非目标

首版实时定位只突出一个主声源。公共结果仍使用列表，以兼容以后支持多声源的自定义算法。

本功能不包含：

- 声源距离或三维位置估计。
- 阵列背面与正面方向消歧。
- 说话人识别、分离或机器学习模型。
- 鱼眼镜头和高阶镜头畸变标定。
- 运行时加载外部 DLL 算法插件。
- 同时保存多套摄像头校准配置。

四点校准拟合针孔相机视角参数，不使用通用单应矩阵。这样可以直接复用现有物理坐标、方向投影和手动视角校准方法。

## 3. 坐标与实时数据口径

阵列坐标继续沿用离线定位约定：

- `+X` 指向阵列右侧。
- `+Y` 指向阵列上方。
- `+Z` 指向阵列正前方。
- 方位角 `0°` 指向正前方，向右为正。
- 俯仰角向上为正。
- 阵列为 6 行 × 8 列，相邻间距 `0.05 m`，通道按从左到右、从上到下编号。

实时定位使用 `AudioProcessor` 完成通道增益和 AGC 后通过 `adjustedFrameReady` 发出的 payload。该口径与录音文件和离线分析一致。每个 payload 包含 `48 × 200` 个 32-bit 小端样本；实时定位工作线程将多个小帧连续累积成算法窗口。

视频点击点以实际视频绘制矩形为基准转换成 `[0,1] × [0,1]` 归一化坐标。控件的黑边和留白不计入视频坐标。

## 4. 总体架构

采用独立实时定位流水线：

```text
设备音频帧
  -> AudioProcessor 增益/AGC
  -> adjustedFrameReady
  -> LiveLocalizationWorker 环形缓冲
  -> ISoundSourceLocator / ISpatialResponseProvider
  -> 方向结果与 SpatialResponseMap
  -> LiveLocalizationPage
  -> 实时视频叠加

设备视频帧
  -> VideoDecoder
  -> MainWindow 最新 QImage
  -> 音视频融合页 + 声源定位页
```

### 4.1 `LiveLocalizationWorker`

新增专用工作对象并移动到独立 `QThread`，职责为：

- 接收增益后的 48 通道实时 payload 和协议时间戳。
- 校验并解交织样本，维护连续的通道优先浮点环形缓冲。
- 按配置窗口长度和更新周期生成最新分析窗。
- 调用当前定位器输出主声源方向。
- 在热力图模式下计算视频方向网格的空间响应。
- 维护最近一段稳定方向历史，服务四点点击采样。
- 丢弃过期计算目标并报告耗时、更新率和错误。

工作线程不得访问 QWidget。页面切换、参数修改、算法切换和校准更新均通过 queued signal/slot 传递。

### 4.2 `LiveLocalizationPage`

新增独立标签页，职责为：

- 接收并显示 `MainWindow` 已解码的最新视频帧。
- 控制实时定位启用状态、算法、显示模式、透明度和置信度。
- 显示方向结果、热力图、处理耗时和状态。
- 管理四点校准交互和五个视角参数编辑。
- 保存和恢复实时定位设置。
- 创建、启动并有界停止实时定位线程。

### 4.3 视频显示基础逻辑复用

从现有视频预览控件中统一封装以下能力：

- 保存最新 `QImage`。
- 按 `KeepAspectRatio` 计算实际视频绘制矩形。
- 在 resize 后重新绘制清晰视频。
- 把控件坐标转换为归一化视频坐标。

“音视频融合”页继续提供双击演示全屏行为；“声源定位”页在相同视频基础能力上增加叠加绘制和校准单击事件。不得让两个页面共享同一个 QWidget 实例。

## 5. 实时窗口与调度

每个协议音频帧只有 200 个采样点。工作线程按通道解交织并写入可覆盖旧数据的环形缓冲，容量至少容纳最大算法窗口和一秒校准历史。

默认配置：

- 采样率：`48000 Hz`。
- 定位窗口：`2048` 样本。
- 定位与热力图更新周期：`100 ms`，约 10 Hz。
- 置信度门限：`0.45`。
- 结果过期时间：`500 ms`。
- 热力图方向网格：目标约 `64 × 36`，按视频宽高比调整。

调度规则：

1. 页面激活且启用定位时才把实时 payload 投递给工作线程。
2. 环形缓冲不足一个完整窗口时只报告“正在积累音频”。
3. 到达更新周期后只分析最新完整窗口。
4. 如果上一次计算仍在执行，不排队所有中间窗口，只保留最新目标。
5. 切换算法、修改关键参数、离开页面或重新进入时清空环形缓冲、平滑状态和旧叠加。
6. UI 使用与当前视频协议时间戳最接近的最近定位结果；结果超过过期时间后隐藏。

进入或离开“声源定位”页不得修改实时通道播放状态。设备连接、视频解码、录音、增益、控制和离线音频分析均保持原状态。

## 6. 定位与真实空间响应热力图

### 6.1 纯标记

纯标记模式调用现有 `ISoundSourceLocator::locate()`。有效结果通过当前实时视频视角参数投影到视频，显示主声源准星、方位角、俯仰角和置信度。

结果为空、低于置信度门限或过期时立即隐藏标记，不保留旧方向冒充新结果。

### 6.2 可选空间响应接口

新增独立的源码级可选接口：

```cpp
struct ScanDirection
{
    double azimuthDegrees = 0.0;
    double elevationDegrees = 0.0;
};

struct SpatialResponseGrid
{
    int columns = 0;
    int rows = 0;
    QVector<ScanDirection> directions;
};

struct SpatialResponseResult
{
    QVector<float> values;
    double reliability = 0.0;
};

class ISpatialResponseProvider
{
public:
    virtual ~ISpatialResponseProvider() = default;
    virtual SpatialResponseResult evaluateSpatialResponse(
        const MultiChannelAudioWindow &window,
        const SpatialResponseGrid &grid) = 0;
};
```

`SpatialResponseGrid::directions` 按行优先排列，数量必须等于 `columns * rows`。`SpatialResponseResult::values` 与其一一对应，返回有限、非负、可相互比较的响应值，数量不匹配视为算法失败。工作线程负责噪声基线扣除、归一化、时间平滑和附加协议时间戳。

`ISoundSourceLocator` 保持不变。自定义算法只实现该接口时仍可用于纯标记；同时实现 `ISpatialResponseProvider` 时可启用真实热力图。页面根据运行时能力启用或禁用热力图选项。

### 6.3 SRP-PHAT

内置 GCC-PHAT 定位器抽取复用的阵元对 PHAT 互相关数据。热力图计算流程为：

1. 按当前视频视角参数把每个低分辨率视频网格中心反投影为阵列坐标系单位方向。
2. 根据每个阵元对几何和声速计算该方向的理论时延。
3. 在对应 GCC-PHAT 相关函数上进行分数延时插值。
4. 按阵元对峰值质量、能量和有效性加权累加。
5. 对空间响应执行噪声基线扣除和 `[0,1]` 归一化。
6. 对相邻时间结果进行短时指数平滑。

热力图是真实方向扫描结果，不是在单一标记周围绘制的视觉光斑。

### 6.4 热力图显示

`SpatialResponseMap` 双线性缩放到实际视频绘制矩形，以半透明蓝、绿、黄、红色阶叠加。默认透明度可调。低能量、无有效阵元对、响应峰不突出或结果过期时隐藏整张热力图。

热力图模式允许同时显示小型主峰准星。主峰方向和纯标记定位结果差异过大时显示诊断状态，但不阻塞后续帧。

## 7. 实时视频视角参数

实时视频使用独立的 `CameraViewSettings`，不与离线静态照片设置共用数值，但复用类型、校验、投影数学和 UI 范围：

- 中心方位角：`[-180°, 180°]`。
- 中心俯仰角：`[-90°, 90°]`。
- 水平视场角：`(1°, 179°)`。
- 垂直视场角：`(1°, 179°)`。
- 画面滚转角：`[-180°, 180°]`。

五个参数始终显示在校准面板。用户修改任意参数后，视频标记与热力图立即重投影；编辑完成后验证并自动保存。页面提供“恢复已保存参数”和“恢复默认参数”。

## 8. 四点自动校准

### 8.1 交互流程

页面提供“开始四点校准”“取消校准”和“清除校准”：

1. 开始校准后隐藏正常定位叠加，但不删除当前已保存参数。
2. 页面提示“第 N/4 点：保持声源稳定并点击视频中的声源位置”。
3. 用户把真实声源放在视频中可见位置并单击其画面位置。
4. 程序从定位线程获取点击前约一秒的稳定方向历史。
5. 质量通过后记录“平均方向、归一化点击点、平均置信度、方向波动”。
6. 四个有效点完成后自动拟合五个物理视角参数。
7. 拟合通过后立即更新、显示并保存参数；拟合失败不覆盖旧参数。

取消校准仅丢弃当前未完成采样。清除校准删除本地四点记录并恢复默认实时视频视角参数。

### 8.2 点击质量门限

点击在以下情况拒绝并给出中文提示：

- 点击不在实际视频绘制矩形内。
- 最近一秒有效定位样本数不足。
- 平均置信度低于当前门限。
- 方位角或俯仰角的加权标准差超过稳定门限。
- 新方向与已有校准方向过近。
- 新点击位置与已有点击位置过近。

角度均值通过单位方向向量加权平均获得，避免直接平均角度在边界附近产生错误。

### 8.3 参数拟合

四点数据提供八个归一化像素观测，用于拟合五个参数：

```text
centerAzimuth
centerElevation
horizontalFov
verticalFov
roll
```

拟合以当前手动参数为首选初值，并增加若干受限初值，通过多起点阻尼最小二乘最小化四个预测投影点与点击点的归一化像素误差。每轮参数都限制在合法范围内。

拟合结果必须满足：

- 数值有限且视角参数合法。
- 四个声源方向和点击点均不退化。
- 优化收敛。
- 总体 RMS 像素误差不超过阈值。
- 不存在单个点的异常大残差。

页面显示四个采集点击点、拟合后的预测点、每点误差和总体 RMS 误差。用户可以在自动结果上继续手动微调五个参数。

### 8.4 分辨率行为

点击坐标以归一化形式保存，视频尺寸变化后自动按当前实际视频矩形适配。不得因为分辨率或宽高比变化主动要求用户重新校准或弹出警告。

## 9. 页面布局与状态

“声源定位”页面布局为：

- 中央：实时视频、纯标记或热力图、校准点击点和预测点。
- 右侧上部：启用定位、算法、显示模式、热力图透明度、更新周期和置信度门限。
- 右侧中部：五个可编辑实时视频视角参数。
- 右侧下部：开始、取消、清除校准，当前步骤、采样质量和恢复参数操作。
- 底部：方位角、俯仰角、置信度、有效阵元对、处理耗时、更新率、视频时间戳和校准 RMS 误差。

使用 `QSplitter` 和 `QScrollArea`，保证 1366×768 下可操作，并保持现有深色工业 HMI 风格。

状态至少包括：

- 等待视频。
- 正在积累音频。
- 定位正常。
- 信号不足或置信度过低。
- 热力图算法不可用。
- 校准第 N/4 点。
- 校准点击被拒绝及原因。
- 校准拟合成功、失败和 RMS 误差。

## 10. 配置持久化

`AppSettings` 新增 `LiveLocalizationSettings`，保存：

- 定位启用状态。
- 算法稳定 ID。
- 显示模式。
- 热力图透明度和更新周期。
- 置信度门限、窗长、声速和平滑参数。
- 五个实时视频 `CameraViewSettings` 参数。
- 最近一次有效四点的方向、归一化点击坐标、置信度和拟合残差。
- 校准数据格式版本。

读取时逐字段验证。校准点数量、数值范围或版本无效时忽略四点诊断记录，但仍可使用合法的五个视角参数。每次成功四点校准或手动参数编辑完成后自动写入本地。下次启动自动载入，不弹出重新校准提示。

## 11. 错误处理与生命周期

错误隔离规则：

- 音频 payload 非法时丢弃该帧并报告状态，不影响 `AudioProcessor`。
- 音频不足、静音、低置信度或定位失败时清空叠加。
- 没有视频时可继续计算和显示角度，但禁止采集点击。
- 算法不支持空间响应时禁用热力图，纯标记可继续工作。
- 自定义算法抛出的标准异常转为页面错误；不得传播到音频处理线程或 UI 事件循环。
- 四点拟合失败时保留旧参数，不写入无效结果。
- 页面离开后停止接收和计算、清空环形缓冲，不改变实时播放或其他设备功能。
- 应用退出时先请求工作线程停止，再有界等待退出；不得永久阻塞主窗口析构。

## 12. 测试策略

### 12.1 实时音频与调度

- 将连续 200 样本帧正确累积为 48 通道算法窗口。
- 验证帧边界、通道顺序和协议时间戳。
- 验证窗口不足时不运行定位。
- 验证页面停用后不再计算并清空旧结果。
- 验证计算过载时只保留最新窗口，不积压所有任务。
- 验证工作线程安全停止。

### 12.2 SRP-PHAT

- 使用已知方位角和俯仰角的合成宽带平面波验证空间响应峰值。
- 验证左右、上下和组合方向。
- 验证静音、随机低相关噪声和异常通道不产生可靠热力图。
- 验证空间响应接口能力发现及纯标记回退。
- 验证网格尺寸、响应值范围和时间平滑。

### 12.3 视频投影与四点拟合

- 验证保持宽高比后的真实视频矩形和黑边点击拒绝。
- 使用已知五个相机参数生成四组点击点，再拟合并验证预测像素误差。
- 验证带有限角度噪声时仍能收敛。
- 拒绝重复方向、重复像素、共线或退化四点。
- 拒绝低置信度和高方向波动点击。
- 验证失败拟合不覆盖旧参数。
- 验证手动修改参数后立即更新投影并持久化。
- 验证不同视频尺寸使用归一化点击点，不提示重新校准。

### 12.4 UI 与功能隔离

- 验证主窗口存在“声源定位”标签和关键控件。
- 验证实时视频帧可同时更新两个页面。
- 验证标记/热力图切换和热力图透明度。
- 验证校准步骤、点击反馈、误差显示和恢复操作。
- 验证进入和离开页面不改变实时通道播放、连接、录音、增益或控制状态。
- 验证结果过期后隐藏叠加。

## 13. 文档与扩展要求

实现完成后更新 `doc/Readme.md` 的模块、线程、页面、配置、算法扩展和变更记录。源码级接口必须注释以下约定：

- 阵列坐标系和方向符号。
- 实时音频窗口排列及归一化范围。
- 空间响应方向网格的顺序和返回值范围。
- 工作线程所有权和 queued 调用边界。
- 定位结果与热力图失效条件。

新增自定义定位算法不应要求修改页面。新增仅支持标记的算法实现 `ISoundSourceLocator`；需要真实热力图时再实现可选 `ISpatialResponseProvider`。

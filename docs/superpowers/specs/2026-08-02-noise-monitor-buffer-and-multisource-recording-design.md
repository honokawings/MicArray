# 降噪监听缓冲与多来源录制设计

## 目标

1. 为降噪页面的实时监听增加有界预缓冲，降低网络、处理线程和音频设备调度抖动造成的断续感。
2. 在降噪页面提供复用录制页参数的快捷开始/停止按钮。
3. 让音频录制页可在“阵列通道”和“降噪数据流”两类来源之间选择。
4. 降噪来源支持同时选择抑制、带通、LogMMSE、AGC 四个数据流节点的输出。
5. 录制多个来源时支持写入一个多通道 WAV，或为每个来源写入可直接播放的独立单声道 WAV。

## 范围与兼容约束

- 阵列通道录制继续使用增益后的 48 通道音频、异步有界队列、整帧分段、JSON 清单和不覆盖保护。
- 来源类型在单次会话内二选一：阵列通道或降噪数据流；不在同一会话混合两类异步链路，避免跨线程时间戳拼接和隐式补帧。
- 降噪处理仍使用移位增益前的原始 CH0..CH3；录制阶段输出与页面实际处理结果一致。
- 不修改设备协议、控制接口、定位链路、音频播放页或既有 WAV 采样格式。
- 不创建分支、不暂存、不提交，不覆盖当前工作区已有改动。

## 方案选择

采用“扩展现有录制线程与 WAV 写入器”的方案，而不是重写通用音频图录制器或增加第二套独立录制器。现有 `AudioRecorder` 继续作为唯一会话状态机和有界异步队列；它根据录制来源接收阵列 payload 或降噪阶段帧，并根据文件布局管理一个或多个 `MultiChannelWavWriter`。

## 监听缓冲

### 配置

`NoiseReductionSettings` 新增 `monitorBufferMilliseconds`：

- 默认 `250 ms`。
- 合法范围 `50..1000 ms`。
- UI 步进 `50 ms`，禁止滚轮误改。
- 通过 `noiseReduction/monitorBufferMilliseconds` 保存；非法值独立回退，不影响其他降噪参数。

### 缓冲模型

新增纯内存 `AudioMonitorBuffer`：

- PCM16 单声道字节先进先出。
- 目标预缓冲等于配置时长；最大容量为目标容量的两倍。
- 只有达到目标字节数后才启动 `QAudioSink`，避免启动后立即欠载。
- 每个输入帧先进入软件缓冲，再按 `QAudioSink::bytesFree()` 写入设备缓冲。
- 设备短写时只丢弃已成功写入的前缀，未写尾部留在软件缓冲等待下一次泵送。
- 超过最大容量时从帧对齐边界丢弃最旧数据，使监听恢复到较新的实时位置并限制延迟。
- 切换来源、开关监听、改变采样率或缓冲时长时关闭音频设备并清空旧缓冲。

## 降噪数据流阶段

新增稳定枚举 `NoiseReductionDataFlowStage`：

- `Suppression`：维纳抑制输出，固定第一阶段。
- `BandPass`：带通节点在当前排序位置处理后的输出。
- `LogMmse`：LogMMSE 节点在当前排序位置处理后的输出。
- `AutomaticGainControl`：AGC 节点在当前排序位置处理后的输出。

`NoiseReductionWorker` 只在录制请求启用时复制所选阶段的 200 个浮点样本并发出 `NoiseReductionRecordingFrame`。节点旁路时仍发布未经该节点修改的连续样本；节点重排时按实际顺序处理并在对应节点之后捕获。绘图、监听和录制共用同一次处理结果，不重复运行 DSP。

## 录制设置与文件布局

`RecordingSettings` 增加：

- `RecordingInputSource inputSource`：`ArrayChannels` 或 `NoiseReductionDataFlow`。
- `RecordingFileLayout fileLayout`：`SingleMultichannelWav` 或 `SeparateMonoWavFiles`。
- 所选 `noiseReductionStages`。
- 与输出通道一一对应的稳定 `trackKeys` 和中文 `trackNames`，用于文件名和清单。

阵列来源沿用真实通道号。降噪来源按用户选择顺序打包到内部临时通道 0..N-1；浮点样本量化为与现有设备 payload 一致的 24 位有效值、32 位小端容器，再复用 WAV 写入路径。

### 单个多通道 WAV

- 保持当前一个写入器、一个清单和整帧分段行为。
- 清单新增来源类型、文件布局、轨道键和显示名称。
- 阵列来源的默认行为与现有版本一致。

### 每来源独立 WAV

- `AudioRecorder::Worker` 为每个来源创建一个 `MultiChannelWavWriter`。
- 文件名为 `<baseName>_<trackKey>.wav`，分段继续使用 `_partNNN.wav`。
- 每个文件为单声道 WAV，可由普通播放器直接播放。
- 任一写入器启动或写入失败即停止整次会话；已成功创建的文件通过各自清单保留真实停止原因，不静默丢弃。
- UI 统计聚合所有音频文件的数据字节与文件字节，输入帧数取所有轨道共同完成的帧数，并显示生成的音频文件数量。

## 页面与状态流

### 音频录制页

- 增加“来源类型”选择。
- 阵列模式显示现有 48 通道矩阵和全选/清空/反选/当前通道命令。
- 降噪模式显示四个阶段复选按钮；至少选择一个来源才能开始。
- 增加“文件布局”选择，录制期间与来源配置一起锁定。
- 启动时根据当前来源构造 `RecordingSettings`，之后不受 UI 临时修改影响。

### 降噪页快捷按钮

- 监听页签增加 `noiseReductionQuickRecordingButton`。
- 空闲且录制页参数有效时显示“快捷开始录制”；会话启动、录制或停止中显示“停止录制”。
- 点击开始完全复用录制页的保存目录、来源、选择项、采样率和文件布局。
- 错误继续显示在录制页，并同步到降噪状态标签。

### 后台激活

`NoiseReductionPage` 分离“页面可见活动”和“录制需要活动”：

- 工作线程活动条件为 `(pageActive || recordingRequired) && processingEnabled`。
- 仅页面离开时清空绘图，不影响正在进行的降噪来源录制。
- 录制进入 Starting 前设置所选阶段并开启 `recordingRequired`。
- 会话回到 Idle/Error、断连或应用退出时解除录制要求并清空阶段捕获。

## 错误与背压

- 降噪页原始帧旁路仍最多保留 32 帧；过载不阻塞主播放、定位、视频或网络线程。
- `AudioRecorder` 继续使用 64 MiB/2048 帧双上限；任一来源排队失败停止整个录制，避免轨道长度悄然分叉。
- 降噪阶段帧缺少所选来源、采样率不一致或样本数不是 200 时作为格式错误拒绝，不写入部分轨道。
- 监听软件缓冲溢出只影响监听并给出一次可恢复警告，不影响录制或 DSP。

## 测试策略

### 媒体测试

- `AudioMonitorBuffer` 的预缓冲、部分消费、PCM16 对齐、最大容量和丢弃最旧数据。
- 降噪工作线程按实际节点顺序发布所选阶段，旁路节点保持连续，关闭捕获时不发布。
- 降噪阶段浮点样本正确量化并写入多通道 WAV。
- 独立布局生成稳定命名的多个单声道 WAV，每个文件头、样本值、清单和统计正确。
- 任一轨道启动/写入失败停止整个会话，不继续接受帧。
- 原阵列多通道录制、增益元数据、分段、队列上限和故障恢复测试保持通过。

### UI 测试

- 录制来源切换显示正确面板，四阶段可多选，空选择禁止启动。
- 文件布局控件存在并在录制期间锁定。
- 降噪快捷按钮复用同一个录制状态，不创建第二会话。
- 降噪来源录制时切换到录制页，工作线程仍接收帧；停止后解除后台活动。
- 1366×768 最低支持尺寸下两个来源面板均无控件重叠或越界。

### 配置与全量验证

- 监听缓冲默认值、往返保存及非法值独立回退。
- Debug 完整构建、6 个 CTest、Python 工具测试、模拟设备自检和 `git diff --check`。

## 非目标

- 不在同一录制会话混合阵列通道与降噪阶段。
- 不自动对齐来自两个不同异步处理线程的轨道。
- 不增加压缩编码、MP3/FLAC、录制回放、定时录制或自动文件上传。
- 不改变降噪算法、节点排序语义、监听增益或已有录制格式。

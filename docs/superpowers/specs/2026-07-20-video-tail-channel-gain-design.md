# 视频帧尾、控制接口与多通道移位增益设计

## 目标

本次变更同时调整视频帧尾判定、控制接口业务模型和 48 通道音频增益链路：

- 视频帧帧尾由单字节 `0x0A` 改为双字节，第一个字节固定为 `0x0A`，第二个字节为任意值。
- UI 和业务模型彻底移除控制接口 6、7，协议编码时仍补两个零值，保持现有 8 路控制帧兼容。
- 为 48 个音频通道增加独立 `-8~+8 bit` 移位增益、手动控制和持续自动增益控制（AGC）。
- 幅值、监听播放和多通道 WAV 录制统一使用增益后的音频数据；高级帧调试仍显示设备原始帧。
- 增益配置支持复位、本地 JSON 保存/载入和 `QSettings` 最近配置恢复。

## 总体架构

采用共享音频增益处理层，避免显示、播放和录制分别实现增益而产生数据不一致：

```text
TCP 字节流
  -> ProtocolCodec
     -> 原始 HostFrame -> 高级帧调试
     -> 音频 payload -> AudioGainProcessor
                         -> 增益后 payload -> AudioRecorder
                         -> 增益后 payload -> AudioFrameDecoder
                                             -> 阵列幅值
                                             -> 监听 PCM
     -> 视频 payload -> VideoDecoder
```

`AudioGainProcessor` 运行在中央音频处理线程。每个成功接受的完整音频帧只执行一次增益变换，再将同一结果分发给录制和解码。协议层不修改音频 payload，以保留原始通信诊断能力。

中央音频输入队列同时限制累计字节数和待处理帧数。队列溢出、格式错误和录制拒绝分别计数并显示，不允许静默丢帧。

## 视频帧尾协议

### 帧结构

视频帧大小改为：

```text
16 字节媒体头 + payloadLength + 2 字节帧尾
```

帧尾规则：

- 第一个尾字节必须为 `0x0A`。
- 第二个尾字节可以是 `0x00~0xFF` 的任意值，但必须存在。
- 第二个字节不参与合法性比较，仅作为实际帧尾的一部分保留和显示。
- 音频帧、心跳帧和控制帧继续按原有双字节 `0A 0D` 判定。

### 解析与诊断

- 只有收到完整的两个视频尾字节后才能提交视频帧；只有第一个尾字节时按 TCP 半包继续等待。
- 第一个尾字节不是 `0x0A` 时产生结构化帧尾错误。
- `frameSize`、累计 `parsedBytes`、帧尾偏移和后续字节预览都按双字节视频帧尾计算。
- 高级帧调试显示两个实际尾字节，例如 `0A 7F`，并标记第二个字节为通配值。
- 帧尾后 16 字节从第二个尾字节之后开始收集。

模拟服务端默认发送 `0A 00`，并通过测试覆盖不同第二字节、缺少第二字节和错误首字节。

## 六路控制接口

### 业务模型

- `ControlValues` 的业务通道数改为 6，只暴露接口 0-5。
- 删除 `ActiveChannelCount`、`isReserved()` 及所有接口 6、7 的 UI、默认值、编辑、预设和撤销逻辑。
- 主界面“控制接口”区域只显示接口 0-5。

### 协议兼容

`0xCC11` 控制帧仍保持原有 26 字节格式：

- 编码器写入业务接口 0-5 的六个 `int16`。
- 编码器在协议末尾自动追加两个 `int16=0`。
- 设备侧仍收到八路控制字段，不需要同步升级协议。

### 配置迁移

- 新控制预设只保存 6 个值。
- 载入旧版 8 路预设时保留前 6 路并丢弃后 2 路。
- 其他长度的预设视为无效，不做部分应用。

## 多通道移位增益

### 通道状态

每个音频通道维护独立状态：

- 模式：`Manual` 或 `Auto`。
- 当前移位值：整数 `-8~+8 bit`。
- 最近原始峰值和增益后峰值。
- 低幅值保持时间和下一次释放调整时间。
- 饱和削顶计数。

移位语义：

- `0 bit`：保持原始幅值。
- 正值：左移放大，每级约增加 `6.02 dB`。
- 负值：算术右移衰减，每级约降低 `6.02 dB`。
- 左移使用 `qint64` 中间值，最终饱和到 `qint32`，禁止整数回绕。

### 两遍处理

每个合法的 `38400` 字节音频 payload 执行两遍处理：

1. 第一遍读取 200 个采样点的 48 通道原始样本，统计每通道峰值并更新独立 AGC 状态。
2. 第二遍按当前移位值处理每个样本，生成保持原排列和小端格式的完整 `38400` 字节 payload。

增益后 payload 是阵列幅值、监听 PCM 和多通道 WAV 的唯一媒体数据来源。

### 手动模式

- 竖向滑条范围为 `-8~+8`，中点为 `0`。
- 用户修改滑条时立即应用，不做音频跳变平滑。
- 用户拖动自动通道的滑条时，该通道切换为手动模式。

### 独立持续 AGC

AGC 不比较通道间幅值，每个通道只依据自身输入：

- 安全峰值上限为有符号 32-bit 满量程的 `80%`。
- 如果当前增益会使本帧超过 `80%`，立即减少足够的移位级数，使当前帧进入安全范围。
- 如果预测峰值持续低于 `35%` 达 `500 ms`，开始提高增益。
- 进入释放阶段后，每 `250 ms` 最多增加 `1 bit`。
- 静音或极低信号不跳过，最终逐步提升到 `+8 bit`。
- `35%~80%` 为滞回区，防止增益在阈值附近反复切换。
- 所有移位值都限制在 `-8~+8`。

“全部自动”使 48 路分别进入独立 AGC；“全部手动”保留各通道当前实际移位值并停止自动调整。

## 阵列幅值界面

“音视频融合 -> 阵列幅值”中的每个阵元改为固定尺寸组合控件：

```text
┌──────────┬──┐
│ CH00     │▲ │
│ 幅值 76% ││ │
│ +3 bit A │▼ │
└──────────┴──┘
```

- 左侧显示通道号、增益后归一化幅值、当前移位值和 `A/M` 模式。
- 左侧背景继续按增益后幅值执行颜色映射。
- 右侧为竖向移位滑条。
- 每个通道提供独立自动模式复选框。
- 自动模式下滑条跟随当前实际移位值。
- 保持 6x8、从左到右再从上到下的通道顺序。
- 在 1366x768 下控件不得重叠；空间不足时只允许阵列页内部滚动，不压缩视频和波形到不可操作尺寸。

阵列工具栏提供：

- 全部自动。
- 全部手动。
- 复位。
- 保存配置。
- 载入配置。

复位会把 48 路设为 `0 bit`、切换为手动模式并清除 AGC 峰值和计时状态，不覆盖已有 JSON 文件。

## 增益配置持久化

### JSON 配置

外部配置文件用于设备标定归档、复制和现场复现：

```json
{
  "schemaVersion": 1,
  "channelCount": 48,
  "shifts": [0, 1, -2],
  "automatic": [false, true, false],
  "agc": {
    "upperPeakRatio": 0.80,
    "lowerPeakRatio": 0.35,
    "releaseHoldMs": 500,
    "releaseStepMs": 250
  }
}
```

示例省略了数组后续元素；实际 `shifts` 和 `automatic` 必须各有 48 项。

- 保存使用 `QSaveFile` 原子替换。
- 载入前完整校验 schema 版本、通道数、数组长度、元素类型、移位范围和 AGC 参数。
- 所有字段全部合法后一次性应用；任一字段错误时保持当前状态不变。
- 载入自动通道时以保存的移位值作为 AGC 初始状态，之后继续自动调整。

### 最近配置

`QSettings` 保存最近一次有效配置，并在下次启动时恢复。外部 JSON 文件路径只作为最近保存/载入目录提示，不要求启动时依赖该文件仍然存在。

## 录制行为

- `AudioRecorder` 只接收增益处理后的 `38400` 字节 payload。
- 录制期间允许手动调节、载入配置和切换 AGC；后续样本立即采用新状态，已写入样本不回溯修改。
- WAV 保持 32-bit 容器、24-bit 有效位及所选通道升序排列。
- 录制清单标记 `gainApplied=true`，并记录开始和结束时的 48 路移位值、自动状态和 AGC 参数。
- 设备断线时停止新的增益输入，完成所有已接受帧，再封口 WAV 和清单。

## 错误处理与诊断

- 非 `38400` 字节音频 payload 在进入增益队列前立即拒绝并记录 `format-error`。
- 录制器再次校验 payload 大小，并同时限制累计待写字节数和待写帧数，防止零长度或异常小帧绕过 `64 MiB` 上限。
- 增益队列溢出、录制队列溢出、格式错误和写盘失败分别统计。
- JSON 载入失败显示具体字段原因，不改变当前通道状态。
- 日志记录配置复位、保存、载入、自动/手动切换、削顶、队列溢出和录制异常。
- 每帧 AGC 变化不写普通日志，避免高频日志淹没有效诊断；UI 使用节流后的状态刷新。

## 测试计划

### 协议测试

- 视频帧接受 `0A 00`、`0A FF` 和其他任意第二尾字节。
- 只有 `0A` 时保持半包等待。
- 第一个尾字节不是 `0A` 时产生帧尾错误。
- 视频帧大小、累计解析字节和 post-tail 16 字节偏移包含第二尾字节。
- 控制模型只接受 6 路，编码帧仍为 26 字节，协议第 7、8 个控制值恒为零。

### 音频与录制测试

- 48 通道正负样本的左移、算术右移、正负饱和和通道隔离。
- 增益后 payload 保持 38400 字节、小端格式和原通道排列。
- 48 路 AGC 独立运行，强信号快速衰减，低信号缓慢增益，静音最终达到 `+8`，滞回区不抖动。
- 幅值、监听 PCM 和 WAV 样本来自同一增益后 payload。
- 非法 payload、零长度高频入队和队列溢出不会产生无界 Qt 排队调用。
- 录制清单正确记录增益状态。

### 配置与 UI 测试

- JSON 保存/载入往返一致。
- 非法版本、错误数组长度、错误类型、越界移位和无效 AGC 参数不会部分应用。
- 旧 8 路控制预设迁移为前 6 路，新预设只保存 6 路。
- UI 不显示接口 6、7。
- 48 个竖向滑条、独立自动状态和批量命令工作正确。
- 幅值颜色和文本使用增益后数据。
- 1366x768 与 1920x1080 下无文本溢出、遮挡和控件重叠。

## 不在本次范围

- 非整数位的精细增益或浮点 DSP。
- 多段压缩器、限幅器、噪声门或跨通道自动均衡。
- 对已录制 WAV 进行离线增益重算。
- 修改设备端控制帧字段数量。

# 降噪数据流横向节点链设计

## 目标

将降噪处理页“数据流”页签中的四个处理节点改为单行横向节点链。无论节点状态和排序如何，四个节点必须同时完整出现在节点链可视区域内，不依赖水平或垂直滚动。

## 布局

- 复用 `ProcessingNodeListWidget`，将流向改为从左到右并关闭换行。
- 禁用水平、垂直滚动条；节点链高度固定为一张紧凑卡片所需高度。
- 在控件尺寸变化时，根据视口宽度、卡片间距和边距动态等分四张卡片的宽度，确保四张卡片的总宽度不超过视口。
- 四个节点之间显示从左到右的流程箭头，使处理顺序清晰可见。
- 卡片正文仅显示节点名称以及“已启用/已旁路”状态；详细参数摘要放入悬浮提示，避免窄卡片因长文本增高或截断主要信息。

## 交互

- 点击任意卡片继续切换下方对应的参数编辑面板。
- “降噪抑制”固定在第一个位置且不可拖动。
- 带通、LogMMSE、AGC 保持内部拖动排序能力，横向拖放完成后继续发送规范化节点顺序并保存到本地。
- 不改变节点旁路、参数编辑、处理线程和音频数据流逻辑。

## 尺寸边界

- 数据流右侧控制区现有最小宽度为 440 像素；节点宽度由实际视口动态计算，不使用会导致溢出的固定宽度。
- 当窗口继续放大时，节点卡片平均扩展；当窗口缩小时，优先保留四张卡片和节点名称，不出现滚动条。
- 若参数摘要较长，只影响工具提示，不参与节点卡片尺寸计算。

## 测试

UI 回归测试验证：

1. 节点列表采用从左到右、禁止换行的单行布局。
2. 水平和垂直滚动条策略均为始终关闭。
3. 四张节点卡片的几何范围均位于视口内。
4. 第一张抑制卡片仍不可拖动，后三张仍可拖动。
5. 节点选择和横向重排仍返回正确的节点标识和后处理顺序。

## 非目标

- 不修改降噪算法、节点参数、处理顺序语义或配置文件格式。
- 不重写为一套新的自定义拖放框架。
- 不增加需要滚动才能访问的节点或额外流程分支。

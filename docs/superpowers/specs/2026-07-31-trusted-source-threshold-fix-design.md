# 实时可信声源阈值修复设计

## 目标

修复实时声源定位中“热力图主峰方向准确，但降低页面置信门限后仍无法判定为可信
声源”的问题，让一个明确、可持久化的总体阈值成为最终可信判定的唯一可调门限，
同时保持对漫射噪声、静音、通道不足、无效 Hessian 和窄带歧义的拒绝能力。

## 根因

实时页面已有 `confidenceThreshold`，配置从 UI 经 `LiveLocalizationSettings`、
`LiveLocalizationWorker` 正确传入 `GccPhatLocator`。定位器最终也使用该阈值比较
`RobustSpatialEstimate::reliability`。

问题位于评分器候选有效性与可信判定的职责混合：总可靠度已经包含有效通道覆盖、
可靠频带覆盖、转向后的全通道相干度、峰旁瓣对比和二维曲率，但
`RobustSrpPhatScorer::refineContinuousPeak()` 又在 `hasDirection` 中硬编码
`steeredChannelCoherence >= 0.15`。定位器先检查 `hasDirection`，再检查用户阈值，
因此隐藏的 `0.15` 会绕过 UI 设置。真实房间的混响、阵元相位误差或频响差异可能
降低全通道相干度，而多基线 SRP 主峰仍位于正确方向，形成现场观察到的漏检。

## 方案比较

### 方案 A：只降低默认总体阈值

改动最小，但隐藏的相干度硬门槛仍可阻止输出，用户调节不具备确定性，不采用。

### 方案 B：暴露所有物理子阈值

可调性最高，但通道覆盖、频带覆盖、相干度、峰对比和曲率彼此耦合，现场人员难以
安全设置，多维组合也更难持久化和验证，不采用。

### 方案 C：候选有效性与总体可信门限分离（采用）

`hasDirection` 只表示候选方向在数学和物理结构上有效：可靠度有限且大于零、二维
Hessian 能生成正的方位/俯仰标准差。相干度继续作为总可靠度中的连续因子，但不再
额外使用固定二值门槛。`GccPhatLocator` 的总体阈值成为唯一可调的可信判定门禁。

## 算法行为

- 不修改多基线 SRP、连续峰位置、热力图值、相干度计算或可靠度五因子公式。
- 移除 `hasDirection` 中重复的 `steeredChannelCoherence >= 0.15` 条件。
- 静音、少于 32 个有效通道、少于 12 个有效基线组、非有限结果、无正定 Hessian
  或可靠度为零仍没有候选方向，任何阈值都不能绕过这些结构性错误。
- `GccPhatLocator::locate()` 和空间响应的 `hasRefinedPeak` 继续使用
  `reliability >= confidenceThreshold`，保证方向、热力图可信标志和状态同源。
- 神经主峰后处理继续要求物理可靠度通过同一个配置阈值，不能提升不可信候选。

## 默认值与配置迁移

实时页面的新默认总体可信阈值为 `0.40`；离线音频分析保持现有 `0.45`，避免改变
离线批处理行为。核心 `LocatorConfiguration` 默认值也保持 `0.45`，训练工具与独立
评分器测试不受实时 UI 默认值影响。

持久化新增首选键 `liveLocalization/trustedSourceThreshold`：

- 新键存在时直接使用并按 `[0,1]` 校验。
- 新键不存在、旧 `liveLocalization/confidenceThreshold` 为旧默认 `0.45` 时，迁移
  到新默认 `0.40`。
- 新键不存在、旧值为其他合法值时，视为用户主动设置并原样保留。
- 保存时写入新键，并同步旧键以保持旧版本回退兼容。
- 非有限或越界值独立回退到 `0.40`，不影响其他实时定位设置。

## UI

现有数值控件保留对象名 `liveLocalizationConfidenceSpin`，标签改为“可信判定阈值”：

- 范围 `[0.00,1.00]`，两位小数，步进 `0.02`，默认 `0.40`。
- tooltip 说明数值越低越容易接受候选，也更可能误报；建议现场从 `0.40` 起调。
- 禁止鼠标滚轮误改，继续支持键盘和步进按钮。
- 修改后立即开启新 processing generation、清空旧方向/热力图、重建定位器并保存。
- 未可信状态继续显示候选可靠度和当前门限，便于直接比较后再调节。

## 测试

### 算法回归

- 构造转向相干度低于旧硬门槛、但 SRP 峰方向误差小且总可靠度高于低配置阈值的
  确定性信号；验证低阈值定位器输出方向，高阈值定位器拒绝，证明调节真正生效。
- 同一信号的低阈值输出误差不超过 `2°`。
- 默认实时阈值下，静音、八组漫射噪声和四种窄带歧义仍不输出方向。
- 有效通道不足和无效 Hessian 仍不能被阈值 `0` 绕过。

### 配置与 UI

- 新键往返、旧默认迁移、旧自定义值保留、非法新键回退分别测试。
- 控件标签、范围、步进、默认值、tooltip 和禁止滚轮行为测试。
- 阈值变化恰好触发一次新 generation 和 worker 重配置，并保存新值。

### 全量验证

- Debug 完整构建和 6 个 CTest 目标。
- 神经 SRP 训练器 `--self-test`。
- 45 个 Python 工具测试和模拟设备服务端自检。
- `git diff --check` 与独立代码审阅。

## 非目标

- 不根据热力图颜色或归一化最大值直接宣布可信声源。
- 不增加多声源检测、自动现场标定或自适应学习阈值。
- 不修改离线分析默认门限、神经模型权重、视频投影或四点校准。
- 不创建分支、不暂存、不提交，不覆盖工作区已有改动。

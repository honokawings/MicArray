# 离线音频分析与声源定位设计

## 1. 背景与目标

MicArray 已能把阵列数据录制为 `WAVE_FORMAT_EXTENSIBLE` 多通道 WAV。新增“音频分析”页面，用于离线打开录音、选择单通道播放，并根据 48 通道同步数据估计一个主声源的方位角和俯仰角。定位结果能够按照用户配置的照片视角参数投影到静态照片上。

本功能必须满足以下目标：

- 流式读取本项目生成的 WAV，不把大文件一次性载入内存。
- 支持选择任意现有通道进行单声道播放、暂停、停止和跳转。
- 使用独立工作线程执行文件读取、播放供数和定位计算。
- 内置 GCC-PHAT/TDOA 鲁棒拟合算法，并提供源码级可扩展算法接口和注册表。
- 对 6×8、水平和垂直间距均为 5 cm 的平面阵列输出正前方半球内的方位角、俯仰角和置信度。
- 使用可配置相机视角把方向投影到 JPG、PNG 或 BMP 静态照片。
- 进入音频分析页时只关闭实时通道监听，不影响连接、接收、视频、控制、增益或录音。
- 保持 Qt 6.5、C++20、Qt Widgets 和现有 MinGW/Ninja 构建环境兼容，不增加第三方运行时依赖。

## 2. 范围与非目标

首版只跟踪当前分析窗中置信度最高的一个远场主声源。算法结果结构使用列表，以便后续算法返回多个声源，但首版 UI 只突出显示主结果。

首版不解决以下问题：

- 阵列背面声源与正面声源的固有前后模糊。
- 近场距离估计和三维位置坐标恢复。
- 多声源分离、说话人识别或机器学习模型推理。
- 鱼眼或非线性镜头畸变校正。
- 运行时加载外部 DLL 算法插件。

## 3. 坐标系与阵列几何

阵列位于 `Z=0` 平面，中心为坐标原点：

- `+X` 指向阵列右侧。
- `+Y` 指向阵列上方。
- `+Z` 指向阵列正前方。
- 方位角 `0°` 指向 `+Z`，向右为正、向左为负。
- 俯仰角 `0°` 位于水平面，向上为正、向下为负。
- 仅输出 `Z>=0` 的正前方半球结果。

通道按 6 行 8 列、从左到右、从上到下排列。通道 `channel` 的行列与物理坐标为：

```text
row = channel / 8
column = channel % 8
x = (column - 3.5) * 0.05 m
y = (2.5 - row) * 0.05 m
z = 0 m
```

因此 CH0 位于左上角，CH7 位于右上角，CH40 位于左下角，CH47 位于右下角。

## 4. 总体架构

### 4.1 UI 与线程

Qt 控件必须留在主线程。新增 `AudioAnalysisPage` 负责界面和状态装配，新增 `AudioAnalysisWorker` 移动到专用 `QThread`，负责：

- 创建、持有和关闭 `WaveFileReader`。
- 创建、持有和停止离线播放使用的 `QAudioSink`。
- 提取所选单通道播放数据。
- 根据实际播放时间或用户选择的位置读取 48 通道分析窗。
- 调用当前 `ISoundSourceLocator`。
- 丢弃过期请求和过期计算结果。

页面与工作线程仅通过 queued signal/slot 通信。工作线程返回文件摘要、播放状态、位置、波形片段、定位结果和结构化错误；不得从工作线程访问 QWidget。

`AudioAnalysisPage` 创建工作线程并在析构时执行有界停止。离开页面时停止离线播放并使工作线程进入空闲状态，但可以保留已打开文件和配置。应用退出时先停止 `QAudioSink` 和定时器，再关闭文件并退出线程。

### 4.2 组件职责

- `WaveFileReader`：解析 RIFF/WAVE、验证格式、定位数据区、执行按样本范围随机读取和通道提取。
- `AudioAnalysisWorker`：实现播放/暂停/停止/跳转状态机，调度分析窗并管理定位器生命周期。
- `ISoundSourceLocator`：定义定位算法的配置和计算接口。
- `SoundSourceLocatorRegistry`：按稳定算法 ID 登记工厂、枚举描述和创建算法。
- `GccPhatLocator`：默认单主声源实现。
- `DirectionProjection`：无 UI 的针孔投影数学模块。
- `DirectionPhotoWidget`：绘制照片、主声源准星和视场外指示。
- `AudioAnalysisPage`：构建页面、验证用户输入、显示状态并持久化页面配置。

上述单位各自放在独立的 `.h/.cpp` 文件中，避免继续扩张 `MainWindow` 和现有实时 `AudioProcessor`。

## 5. WAV 读取与播放

### 5.1 支持的格式

`WaveFileReader` 支持 RIFF/WAVE 中的整数 PCM：

- 格式码 `WAVE_FORMAT_PCM (0x0001)`。
- 格式码 `WAVE_FORMAT_EXTENSIBLE (0xfffe)` 且 SubFormat 为 PCM GUID。
- 16、24 或 32 bit 整数容器；有效位数必须大于 0 且不超过容器位数。
- 1～48 通道、小端、交织采样。

本项目生成的文件为 32-bit 容器、24-bit 有效位、`WAVE_FORMAT_EXTENSIBLE`。读取器按 RIFF chunk 遍历 `fmt ` 和 `data`，安全跳过未知 chunk，并处理奇数字节 chunk 的填充。不得假设 `data` 固定在偏移 60。`blockAlign`、`byteRate`、数据长度和完整样本帧数必须相互一致；末尾不足一个完整采样帧的数据视为截断错误。

读取器使用 `qint64` 保存文件偏移和样本位置。单个 RIFF 段仍受 32-bit chunk 长度限制，但分段录音生成的每个 WAV 可独立打开。

### 5.2 通道映射

单通道播放支持任何合法通道数。声源定位只在 WAV 恰好有 48 通道时启用，并把 WAV 通道索引直接映射到物理 CH0～CH47。少于 48 通道的录音仍能播放，但页面明确显示“通道数不足，无法定位”。

### 5.3 播放状态机

工作线程维护以下状态：

```text
Closed -> Loaded -> Playing
Playing -> Paused -> Playing
Playing/Paused -> Loaded (Stop)
Loaded/Playing/Paused -> Closed (Close or load another file)
```

播放使用单声道 PCM16。读取器将整数样本按有效位归一化，再饱和转换为 `qint16`；本项目 32/24 格式等价于按 24-bit 有效量级缩放，不直接截取错误的高低字节。

界面提供：

- 打开文件。
- 播放/暂停、停止。
- 时间进度显示和拖动。
- 当前监听通道选择。
- 音量控制。

切换通道时保持当前时间位置并刷新后续输出。跳转时停止并重建音频输出周期，清空旧缓冲，避免旧通道或旧位置数据继续播放。

工作线程使用 `QAudioSink::processedUSecs()` 加上本次播放起点计算实际听到的时间位置，而不是仅使用已写入字节数。每次跳转或重新开始播放都会重置该时间基准。暂停状态允许跳转并立即分析新位置。

## 6. 定位接口与注册表

### 6.1 公共数据类型

接口使用与具体算法无关的数据：

```cpp
struct MicrophonePosition
{
    double xMeters = 0.0;
    double yMeters = 0.0;
    double zMeters = 0.0;
};

struct LocatorConfiguration
{
    QVector<MicrophonePosition> microphones;
    int sampleRate = 48000;
    int windowSamples = 2048;
    double soundSpeedMetersPerSecond = 343.0;
    double confidenceThreshold = 0.45;
    double smoothingFactor = 0.35;
};

struct MultiChannelAudioWindow
{
    QVector<QVector<float>> channels;
    qint64 centerSample = 0;
    int sampleRate = 48000;
};

struct SoundSourceDirection
{
    double azimuthDegrees = 0.0;
    double elevationDegrees = 0.0;
    double confidence = 0.0;
    double residualSamples = 0.0;
    int validPairCount = 0;
    qint64 centerSample = 0;
};
```

音频窗为通道优先、归一化到 `[-1, 1]` 的浮点数据。`windowSamples` 必须为 512～8192 范围内的 2 的幂；首版默认 2048。默认更新周期为 50 ms。

### 6.2 算法接口

```cpp
class ISoundSourceLocator
{
public:
    virtual ~ISoundSourceLocator() = default;
    virtual LocatorDescriptor descriptor() const = 0;
    virtual bool configure(const LocatorConfiguration &configuration,
                           QString *errorMessage) = 0;
    virtual QVector<SoundSourceDirection> locate(
        const MultiChannelAudioWindow &window) = 0;
};
```

`LocatorDescriptor` 至少包含稳定 ID、中文显示名称和说明。算法 ID 不随 UI 文案变化。

`SoundSourceLocatorRegistry` 接受 `std::function<std::unique_ptr<ISoundSourceLocator>()>` 工厂。重复 ID 注册失败并返回错误。自定义算法只需实现接口，在集中注册函数中登记，即可出现在算法下拉框；不要求修改分析页。

接口结果是列表。默认 GCC-PHAT 实现返回零个或一个结果。零结果表示当前窗没有可靠方向，UI 不得用旧角度伪装为新结果。

## 7. 默认 GCC-PHAT 定位算法

### 7.1 信号处理

每次定位执行以下步骤：

1. 验证 48 通道、相同窗长、有限样本和采样率。
2. 每通道去直流、加 Hann 窗并计算能量。
3. 静音或总能量低于数值稳定门限时返回空结果。
4. 对每通道执行零填充 FFT；2048 样本窗默认使用 4096 点 FFT。
5. 对覆盖水平、垂直和多种基线长度的确定性阵元对集合计算 GCC-PHAT。
6. 仅在阵元对几何决定的物理最大时延内搜索相关峰，并进行抛物线峰值插值。
7. 根据主峰突出度、峰旁瓣比和通道能量生成阵元对权重。
8. 剔除不满足物理时延、权重过低或与当前拟合明显冲突的阵元对。
9. 使用加权鲁棒最小二乘求解平面内方向分量 `ux`、`uy`。
10. 当 `ux²+uy²<=1` 时取正根 `uz=sqrt(1-ux²-uy²)`；超出单位圆且无法由容差修正时返回空结果。

TDOA 模型为：

```text
deltaTime(i,j) = dot(position_i - position_j, direction) / soundSpeed
```

角度计算为：

```text
azimuth = atan2(ux, uz)
elevation = atan2(uy, sqrt(ux² + uz²))
```

结果限定在正前方半球。

### 7.2 置信度与平滑

置信度综合以下因素并限制到 `[0,1]`：

- 通过校验的阵元对占比。
- GCC 主峰质量。
- 鲁棒拟合内点占比。
- 时延残差。
- 当前窗信号能量。

低于用户门限的结果仍可用于诊断文本，但不会更新照片准星。时间平滑对单位方向向量执行指数平滑后重新归一化，避免直接对角度平滑造成边界跳变。跳转、打开新文件、切换算法或长时间无可靠结果时重置平滑状态。

默认参数：

- 窗长：2048 样本。
- 更新周期：50 ms。
- 声速：343 m/s。
- 置信度门限：0.45。
- 平滑因子：0.35，新结果权重为 0.35。

这些参数由页面配置并在合法范围内持久化。

### 7.3 调度与过载保护

播放期间以实际播放位置为中心读取分析窗。离线文件允许读取当前位置两侧的数据；文件首尾不足部分补零，并降低有效数据比例对应的置信度。

每个分析请求携带递增请求序号和中心样本位置。打开新文件、跳转、切换算法或修改关键参数时增加序号。UI 只接受当前序号的结果。若计算耗时超过更新周期，不排队积累所有时间窗；工作线程保留最新目标位置并丢弃中间过期请求。

## 8. 照片方向投影

### 8.1 相机参数

用户可选择 JPG、PNG 或 BMP。视角配置包含：

- 照片中心方位角，默认 `0°`。
- 照片中心俯仰角，默认 `0°`。
- 水平视场角，默认 `90°`。
- 垂直视场角，默认 `60°`。
- 相机滚转角，默认 `0°`。

合法范围：中心方位 `[-180°,180°]`，中心俯仰 `[-90°,90°]`，水平和垂直视场 `(1°,179°)`，滚转 `[-180°,180°]`。

### 8.2 针孔投影

先把阵列坐标系中的单位方向向量按相机中心方位、中心俯仰和滚转的逆旋转变换到相机坐标系 `(xc,yc,zc)`。当 `zc<=0` 时方向在相机背后，视为视场外。否则归一化图片坐标为：

```text
u = 0.5 + xc / (2 * zc * tan(horizontalFov / 2))
v = 0.5 - yc / (2 * zc * tan(verticalFov / 2))
```

`u`、`v` 均位于 `[0,1]` 时显示照片内准星。超出范围时，沿照片中心到投影点的方向与图片边界求交，绘制边缘箭头和“视场外”。

`DirectionPhotoWidget` 使用 `KeepAspectRatio` 计算真实图片绘制矩形，所有投影坐标相对于该矩形计算，不能把控件留白算入照片像素范围。

### 8.3 标记样式

有效主结果绘制圆形准星，并显示方位角、俯仰角和置信度。颜色按置信度从红到黄再到绿映射。置信度低于门限、结果为空或文件不可定位时隐藏准星并显示中文状态。绘制 API 接受结果列表，以便后续显示多声源。

## 9. 页面交互

主窗口标签顺序新增“音频分析”，页面由 `AudioAnalysisPage` 自己构建。布局为：

- 顶部：WAV 路径、打开按钮、文件格式摘要、照片路径和选择按钮。
- 左侧：播放/暂停、停止、时间进度、监听通道、音量和当前时间。
- 中部：照片与动态方向标记。
- 右侧：算法、声速、窗长、更新周期、平滑因子、置信度门限和照片视角参数。
- 底部：当前通道波形、方位角、俯仰角、置信度、残差、有效阵元对数量和处理耗时。

使用 `QSplitter` 和必要的 `QScrollArea`，保持 1366×768 可操作，并复用现有深色工业 HMI 风格。

进入音频分析标签时：

1. 若实时音频播放复选框已启用，则取消选中。
2. 通过现有配置路径把 `playbackEnabled=false` 投递给实时 `AudioProcessor`。
3. 不改变设备连接、接收队列、视频解码、录音、增益或控制状态。

离开音频分析标签时停止离线播放。实时播放保持关闭，不自动恢复；用户回到“音视频融合”页后可主动重新启用。

## 10. 配置持久化

`AppSettings` 增加音频分析配置，保存：

- 最近 WAV 路径和最近照片路径。
- 监听通道和音量。
- 算法稳定 ID。
- 窗长、更新周期、声速、平滑因子和置信度门限。
- 照片中心方位、中心俯仰、水平视场、垂直视场和滚转。

读取设置时逐字段验证。无效值回退到上述默认值，不影响其他设置组。重置应用设置时一并恢复音频分析默认值。

## 11. 错误处理与隔离

以下情况以中文错误或状态返回，不得影响实时设备链路：

- 文件不存在、无权限、不是 RIFF/WAVE、格式不支持或数据截断。
- 通道索引无效、采样范围越界或读取失败。
- 声卡不支持目标格式、无法启动或写入失败。
- 非 48 通道、静音、有效数据不足、相关峰不可靠或拟合失败。
- 算法 ID 不存在、配置拒绝或自定义算法抛出可捕获异常。
- 图片不存在、无法解码或相机参数不合法。

工作线程错误只停止相关播放或分析动作。打开新文件失败时保留当前已成功加载文件；应用退出时不得因分析线程未停止而永久阻塞，超时需记录生命周期错误。

## 12. 测试策略

### 12.1 WAV 与播放数据

- 解析本项目 32-bit 容器/24-bit 有效位扩展 PCM。
- 解析合法标准 PCM 16/24/32。
- 支持未知 chunk、奇数字节填充和非固定 `data` 偏移。
- 拒绝错误 RIFF 长度、非法 blockAlign、非 PCM SubFormat 和截断采样帧。
- 验证 48 通道行优先映射和每个通道的随机范围读取。
- 验证 PCM32/24 到 PCM16 的符号、缩放和饱和。
- 验证切换通道、停止和跳转后的样本位置。

### 12.2 几何、定位与注册表

- 验证 CH0、CH7、CH40、CH47 和阵列中心对称性。
- 使用具有已知分数时延的合成宽带平面波，验证正前方、左右、上下和组合角度。
- 在可重复白噪声、通道增益差异和少量异常阵元对条件下验证角度容差和置信度。
- 静音、非法通道数、超物理时延和低相关数据返回空结果。
- 验证单位方向平滑和重置行为。
- 验证注册、枚举、按 ID 创建和重复 ID 拒绝。

### 12.3 投影与 UI

- 验证相机中心、水平/垂直边缘、滚转和相机背后方向。
- 验证图片按比例缩放后的留白不影响投影坐标。
- 验证视场外箭头与低置信度隐藏。
- 验证进入音频分析页会关闭实时监听，但不改变连接和录音状态。
- 验证离开页面停止离线播放，析构后工作线程退出。
- 验证少于 48 通道时播放可用而定位控件禁用。

# UART 串口收发

### 2026-10-11 音频控制与直流诊断

按硬件仓库更新后的 `doc/system_uart_debug.md` 适配 `SYS3 / I2S1 / GAIN1` 三种回帧。SYS3 仍为 34 字 / 312 字节，新增内容是 word8 的直流诊断位和独立的音频命令，不改变 M128 UDP 格式。以下 2026-10-02、2026-09-21 记录保留各自当时的验证结论，不代表当前协议仍只有单字节命令。

“设备诊断→UART 串口”分为“系统状态 / 音频控制 / 原始字 / 事件记录”。音频页的常用控制并排成两组；请求值和实际值三行完整常显，1120×700 下不需要滚动。详细域时效、音频标志和完整操作结果可在状态提示中查看；控件不会被收到的回执自动改写。

## 板端音频控制

1. 连接串口并等待新鲜 SYS3。连接不会自动发送命令；先点击“查询监听”或“查询增益”，识别新版音频回帧后才开放设置。旧位流查询超时会明确显示未知，不自动降级发送其他设置。
2. “板端 I2S 监听”选择 CH0–127，点击“启用监听”。“关闭监听”发送 OFF，保留通道且 I2S 时钟继续运行。板端监听与本机扬声器监听互相独立。
3. “奇偶增益”以倍率输入，分别作用于所有偶数/奇数通道。合法编码为非负 Q2.22 `000000–7FFFFF`（0 至约 2×）；`400000=1×`、`200000=0.5×`、`300000=0.75×`。悬停输入框可查看实际编码，状态表同时显示倍率和 HEX。“填入 1×”仅填入参数，不发送；0× 会将对应组真实音频归零。
4. “载入最近请求”仅把回执里的请求通道和奇偶增益填入输入框，不发送命令。历史请求值会标为“历史”；实际状态过期时显示“—（当前值未知）”，请重新查询。
5. 操作期间锁定参数和其他串口发送；增益设置在途时还会锁定新录制。录制或写盘中禁止应用增益、系统复位和自测切换；只读查询和板端监听选择/静音仍可使用。增益会改变设备输出音频，而不仅是监听音量。

| 按钮 | 发送内容（末尾 LF） | 回帧 |
|---|---|---|
| 查询监听 | `@I2S?` | I2S1 |
| 启用监听 | `@I2S=0` 至 `@I2S=127` | I2S1 |
| 关闭监听 | `@I2S=OFF` | I2S1 |
| 查询增益 | `@GAIN?` | GAIN1 |
| 应用增益 | `@GAIN=EEEEEE,OOOOOO`，六位大写 HEX | GAIN1 |

设置只发送一次，收到对应音频回执后按 200 ms 间隔逐次进行只读确认查询；前一条查询尚未回应时不再发送下一条。即使首个回执的实际值已经一致，仍需后续查询确认。只有请求/设备保存/实际值一致、Fresh=1、Pending=0、AudioResetReleased=1、ErrorCode=0、QueueOverflows=0 才报告“已确认生效”。5 秒未完成、语法/越界错误、队列溢出、值不匹配、外部旧命令干预、重启或串口中断都会结束本次操作，**设置不自动重试**；迟到回执只能保留为证据。

I2S1 / GAIN1 各为 14 个八位大写十六进制字、单空格、CRLF，分别严格为 132 / 133 字节；独立音频序号由两种回帧共用，不纳入 SYS3 命令计数或序号缺口。支持任意分片以及与 SYS3 混合接收，重复回帧不刷新时效。主机回帧时效为 1500 ms；Fresh=0 或音频复位未释放时实际配置和音频计数也显示未知，不能仅凭复位释放位证明时钟/数据正常。

音频页显示所选通道 PCM 样本、I2S 输出帧、欠载帧、串行验证/错误和最近有符号 PCM24；原始字页可选择 SYS3 的 34 字或最近音频回帧的 14 字。诊断报告在 `sys3_uart.audio_uart` 中保留独立计数、操作状态和原始字，过期或无效实际字段写 `null`，请求历史和原始取证字不删除。解码/确认只使用 I2S 的低 8 位和增益的低 24 位，保留位不参与数值比较。

### 直流补偿与自测解释

- SYS3 word8 bit12/13/14 分别为“直流补偿配置使能 / 估计审核结束 / 存在拒绝通道”，在系统状态表、音频页和 JSON 中显示。旧位流没有这些位，全部为零不能证明当前位流支持直流诊断或确认关闭补偿。
- “估计审核结束”不等于所有通道正常；存在拒绝通道时需结合饱和标志和通道质量排查。UART 未定义每通道直流值回读，本软件不伪造该数据，也不增加直流配置命令。
- 内部 PDM 自测由新鲜 SYS3 的 SelftestMode 判定；该模式旁路奇偶补偿和直流处理，使用 unity 验证数据。GAIN1 的实际值仍是音频域已生效的配置寄存器，非 unity 配置不表示 BIST 样本已经缩放。
- 支持上述协议不代表自动识别 `FIR8` 等位流身份；电气、DAC 模拟输出与真实声学效果仍需板级验证。

## 使用入口

“设备诊断→UART 串口”；也可从“系统配置→接口设置→打开串口面板”进入。选择/输入实际端口后点击“连接串口”。默认 COM3，固定 115200 / 8N1 / 无流控，UART 电平 3.3 V。关闭占用同一端口的其他串口助手。端口选择可保存，但启动不自动连接，连接不自动发命令。

硬件需输出 `SYS3`，`CLK2` 不能用于此面板。SYS3 识别不等于位流身份验证，更不能检测 1.8 V MEMS 供电是否正确。

## 命令与保护

| 按钮 | 字节 | 行为与完成判定 |
|---|---|---|
| 读取状态 / 状态别名 | s / h | 请求快照；识别回执后仍须分别检查各时钟域的新鲜标记 |
| 系统复位 | r | 二次确认，录制/写盘中禁用；先停止主机 UDP，发送后观察新鲜音频域、时钟恢复、音频复位释放、校准完成及已加载实采模式；不声称测量了复位脉宽；请手动重新开始 UDP 接收 |
| 切换自测 | t | 二次确认，录制/写盘中禁用；新鲜音频/以太网域及正常时钟才可发送；间隔至少 200 ms，后续快照须确认模式改变、新 epoch、正常时钟、音频复位释放和校准已加载对应模式 |
| 清时钟历史 | c | 二次确认；后续快照检查时钟历史掩码清零，不等于清除当前故障、PHY/MAC 计数或采集错误 |

上述五种旧 SYS3 命令均为单字节，不加 CR/LF；新增音频命令见“板端音频控制”。旧命令识别依据是 16 位命令计数恰好递增一次（支持回绕）且最近字符匹配。`r/t/c` 必须再看到后续递增快照，不能把同一条识别回执直接当成完成。出现外部命令干预、观察域重启或断连时结果标为未知；5 秒未确认则超时，**不自动重试**。任何时刻最多有一条串口操作待处理，不建立后台命令队列。

连接中有效 SYS3 帧超过 1500 ms 未递增时禁用发送；重复帧不能刷新时效。发送线程取出命令前再次检查时效，超过 200 ms 尚未发送的请求丢弃；命令计数改变时取消待发送请求，模式切换还会重新检查音频/以太网域、时钟、模式及 epoch 是否保持原基线。确认框默认选择“不执行”。

自测切换的 200 ms 冷却在发送出队时预留，并在实际成功写入字节后重新计时，不按界面点击时间扣减。录制状态同时传到发送线程，出队前再次禁止 `r/t`；开始录制即时设置互锁，不等待界面定时刷新；`r/t` 在途时录制页和快捷录制均禁止启动新录制。

每次处理输入前先检查 5 秒命令期限，迟到回执或迟到的完成状态不会把超时结果改为成功。观察计时倒退（排除自然回绕）会使在途命令结果失效，即使设备重启后帧号恰好相同或更大，也不会继续确认旧命令。

## 状态与报告

- 严格解析 312 字节：`SYS3 `、34 个八位大写十六进制字、单空格分隔、CRLF。支持任意串口分片和多帧合并；过长行有界丢弃并从下一行恢复。
- 观察域状态与音频、以太网（含 PHY/MDIO/MAC）、RX 域分别标注“新鲜/历史/未知”。域新鲜位为零时不会冒充当前读数；串口断开/全局超时后所有域均为历史数据。
- 显示时钟掩码与相对频率、采集/校准/自测、PHY/MDIO/PHYSR、ARP、UDP TX、RX 计数等；另提供完整 34 字的 HEX、十进制和域时效表。
- MDIO 写事务的 ACK 显示“不适用”；扫描时读无 ACK 不自动判定设备故障。FPGA `UdpSent` 与 TX BIST 不代表 PC 已收到或逐样本验证通过。
- 最近 400 条原始行/收发事件在界面和日志导出中保留；超出会丢弃最旧记录，不是无限时长取证。诊断 JSON 增加 `sys3_uart`，记录连接、全局/分域时效、原始字、命令状态、连续性计数和日志。
- 接收驱动报告丢字节/线路错误时清空旧残片，丢弃至下一换行后重新识别完整帧；在途命令结果标未知。原生队列超过 4096 字节时进入积压保护，历史输入只计字节数、不解码为当前状态；排空并收到新完整快照后解除禁发。`receive_backlog`、`receive_discontinuities` 和界面“接收中断”计数明确记录这一边界。
- 观察域、音频域的五位控制器状态分别解码，另显示 TX 使能、数据包就绪、ARP 应答待发及 TX 排空；均保持各自所属域时效。未把原控制器状态擅自解释成单一心跳。
- `hardware_reference.uart_supported_by_host=true` 表示软件具备能力，不表示串口已连接。位流身份、电压、真实接线和声学性能仍需外部确认。

## 实现与依赖

`audiouartprotocol.*` 实现音频命令编码与回帧解析；`sys3protocol.*` 为可独立回归的混合解析/会话状态；`sys3client.*` 用 Windows 原生串口和独立 QThread；`sys3panel.*` 为界面。Qt 套件没有 SerialPort 模块，因此无需安装或部署额外 QtSerialPort DLL。原 48 通道源码及 M128 UDP 格式不变。

端口独占打开，DTR/RTS 关闭，读采用立即返回模式，写超时 250 ms，UI 不执行串口 I/O。实现参考 Microsoft 的 [COMMTIMEOUTS](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-commtimeouts) 和[串口资源句柄](https://learn.microsoft.com/en-us/windows/win32/devio/communications-resource-handles)说明。非 Windows 构建明确返回不支持，而非伪造连接成功。

可使用 `MicArray128.exe --serial-port COM3 --smoke-seconds 5 --report <新路径> --screenshot <新路径>` 做有时长限制的只读接收。不会自动发送任何命令；`--smoke-seconds` 使用隔离测试设置，不保存测试端口到操作员配置。

# M128 螺旋阵列上位机

本目录是独立的 **128 通道** Qt6 上位机，不是旧 48 通道程序的通道数开关。开发分支为 `SpiralArray`；本次开发不提交 Git。该分支从仓库根目录配置 CMake 时默认构建新 128 应用；只有显式设置 `-DMICARRAY_BUILD_LEGACY_48=ON` 才构建原应用，二者不会混合编译。

## 独立性与目录

- `src/`：M128 UDP、SYS3 串口、诊断、自测、128 路 DSP、录制、USB 摄像头与界面。
- `resources/selftest_pcm.bin`：经过 SHA-256 校验的官方 pattern_id=1 参考表，编译进资源，不需要 FPGA 工程在场。
- `tests/fixtures/`：官方真实 RTL 仿真报文；`tests/test_array128.cpp` 覆盖协议、关键链路和界面，`tests/test_imaging.cpp` 使用独立传播距离模型验证 128 通道成像。
- `tools/m128_tool.py`：独立标准库探针和模拟发送器。
- `doc/host_protocol_reference.md`：2026-09-20 同步的接口参考副本。原文相对链接指向硬件仓库，不是此目录的运行依赖。
- `doc/SpecAudit-2026-09-20.md`：与最新硬件 README 的规格核对、UI 命名及未实现边界。
- `doc/Sys3Serial.md`：串口使用、命令确认、回归与实机验证边界。
- 独立可执行程序 `MicArray128.exe`，独立设置 `MicArray/MicArray128`；不会读取旧程序配置。
- 只复用上一级 `src/` 中不含设备协议的 FFT、投影、四点拟合、维纳/带通/LogMMSE/AGC 和监听 FIFO 源码。WAV 读取器仅用于录制文件回归测试，不编译进生产程序。旧 `main.cpp`、TCP、48 路解码器、配置与界面不编译进新目标；旧神经权重不用于螺旋阵列。

## 构建与启动

Qt 6.5+，C++20，组件 Core/Gui/Widgets/Network/Multimedia/MultimediaWidgets/Test。开发机已配置的命令：

```powershell
$env:PATH = 'D:\Application\ProgramingIDE\Qt6\Tools\mingw1310_64\bin;D:\Application\ProgramingIDE\Qt6\6.11.1\mingw_64\bin;' + $env:PATH
cmake -S array128 -B build-array128 -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=D:/Application/ProgramingIDE/Qt6/6.11.1/mingw_64 -DCMAKE_CXX_COMPILER=D:/Application/ProgramingIDE/Qt6/Tools/mingw1310_64/bin/g++.exe
cmake --build build-array128
ctest --test-dir build-array128 --output-on-failure
.\build-array128\MicArray128.exe
```

若 PATH 中有其他 MSYS/MinGW，请使用 Qt 套件的 CMake/Ninja/编译器，避免混装运行库。

统一发布命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-release.ps1`，当前分支默认选择 128 版；也可显式 `-Variant Array128`。脚本自动恢复缓存中的 Qt 工具链，构建并运行关键 CTest，部署运行库，并在 `dist/MicArray128-Release-时间戳-唯一标识/` 生成发布目录和同名 ZIP。每次新建，不覆盖旧包；`-NoZip` 仅生成目录，`-SkipTests` 仅在已有测试结果时使用，`-PlanOnly` 可无副作用查看方案。

`array128/package.ps1` 保留为委托上述实现的快捷入口，原 `-QtKit`、`-QtTools`、`-SkipTests` 参数仍可用，输出同样使用唯一包目录。若仅需更新固定的开发部署目录，仍可手动运行 `cmake --install build-array128 --prefix D:/Workspace/QT/MicArray/dist/MicArray128`（Qt 部署要求绝对路径）。新旧程序资源保持分离，发布脚本不会修改防火墙。完整参数见 [`scripts/Readme.md`](../scripts/Readme.md)。

## 接入硬件

1. PC 千兆网卡设为 `192.168.10.1/24`，FPGA 默认 `192.168.10.2:5000`。本机默认监听所有 IPv4 地址的 UDP 5000，但只接受配置的源 IP 和源端口。
2. Windows 需要允许该可执行程序接收上述 UDP 入站流量；程序不会自动修改网卡或防火墙。
3. 点击“开始接收”。硬件就绪后自动发送，不需要启动命令；UDP 链路不发送 TCP、心跳、方向、模式或 ACK 命令。停止接收只关闭 PC socket；SYS3 串口操作独立于 UDP。
4. 选择连接 PC 的 USB 摄像头后点击“打开视频”。摄像头与 FPGA 不存在硬件同步，不能声称音视频样本精确对齐；没有摄像头时可使用方向网格或静态照片。
5. “设备诊断→SYS3 串口”可枚举/选择端口并连接，默认 COM3、115200 8N1、无流控。连接时只接收，识别新鲜 SYS3 后开放 `s/h/r/t/c`；复位/切换/清历史需要界面确认。录制中禁止复位和切换；复位前暂停 UDP，恢复后手动重新接收。KEY0/KEY1 兼容保留。只有 `flags.bit4=1` 的包参与自测表比对；自测流禁止进入定位和波束降噪，但可监听、查看电平和录制证据。

新版参考构建为 `MEMS_Array_uart_clk8_18v_spread3_long`，麦克风 IM72D128V01，8 路同源 CLK0–7，MEMS 接口 LVCMOS18 / 1.8 V；UART 为 3.3 V，两者不可混淆。J10/J25 属 L6，J26 属 L7；跳线、供电及真实位流须人工确认。UDP 不携带位流身份或供电测量值。

## 页面与操作组织

主页面统一为“实时监测 / 声源定位 / 定向降噪 / 音频录制 / 系统配置 / 设备诊断”。128 版已删除离线分析页面和工作线程。顶部常驻接收状态、开始/停止、视频选择和数据时效；未知、等待、自测、质量故障与实采使用文字和状态色共同区分。错误提示常显直到关闭或重新开始接收；绑定失败后自动恢复可编辑、可重试状态。

“系统配置”分为“接口设置 / 阵列几何 / 硬件规格”。网络参数在接收期间锁定；顶部“接口设置”和“阵列配置”按钮直达对应子页。几何表常显通道、DATA/LR、接口/Bank、FPGA 焊盘和实际坐标，无坐标时为“—”。硬件规格明确为 README 参考，不是设备回读。

定位校准将中心方位/俯仰和水平/垂直视场角成对排列，四点表完整常显；参数标签标明单位。数值及下拉控件禁止滚轮误改。录制来源采用“原始通道 / 处理节点”，文件布局采用“独立音轨 WAV / 多通道 WAV”；完整含义见提示。

监听、定位和降噪显示各自准备条件，不把“已勾选”当作“正在处理”。录制显示勾选轨数、未就绪原因、写盘中和完成状态；开始按钮与快捷按钮按同一条件启用，两种来源各自的勾选、最后来源及保存布局跨启动保留，录制/写盘中锁定目录及选择操作。带通边界相互约束，始终满足下限小于上限，不再静默旁路。

监测页通道网格支持方向键和 Home/End；停止或超时后电平灰显、波形/频谱标注历史快照。1120×700 紧凑窗口在显示常显告警时仍保留完整128通道网格。接收恢复后会区分“正在实采但有历史告警”和“接收异常已停止”，历史事件不会被正常包抹除。深浅色、焦点框、上下箭头及禁用参数样式统一；数值框和下拉框仍禁止滚轮误改。

## 调试页面

默认打开“设备诊断”，包含五个子页：

- **运行状态**：通信、信号质量、数字自测和硬件状态分区显示，不能以“仍在收包”替代健康判定。无数据时显示未知，停止/超时后提示历史数据。
- **通道质量**：CH、DATA/LR、接口/Bank、RMS/AC-RMS/直流分量、精确满量程削顶、零值数、相邻相同值、自测错误分布；提示显示 FPGA 焊盘。CLK 的负载分组由实际接线决定，不能按 CH/32 或 CH/16 推定。电平单位 dBFS，未进行灵敏度校准时不显示 Pa/dBSPL。
- **数据报文**：头字节、u64 包号/帧号、epoch、六状态位、相对有效时间、包号和帧号独立审计。所有 64 位计数在 JSON 中写十进制字符串。
- **SYS3 串口**：连接、手动单字节命令、时钟/采集/PHY/MDIO/ARP/TX/RX 状态、34 个原始字与最近 400 条日志。严格 312 字节帧解析；超过 1500 ms 未收到递增有效帧时判过期，音频/以太网/RX 域另检查快照新鲜位。SYS3 不是位流身份验证。
- **联调指引**：1.8 V 供电/接线、SYS3 UART、网络、自测、MEMS 实采与时间轴解释。“事件记录”按需展开，常态不占用诊断区域。

SYS3 命令不自动重试；发送前状态变化则取消请求，超时后的迟到回执不能改判成功。切换自测需音频和以太网快照均新鲜，并按新 epoch、复位释放及校准加载模式确认完成；设备观察计时重启时旧命令结果失效。详细保护与验证记录见 [SYS3 串口说明](doc/Sys3Serial.md)。

目标稳定速率为 16,000 包/s、48,000 PCM 帧/s、19.328 MB/s（154.624 Mbit/s）UDP 负载；含线路开销预算为 163.072 Mbit/s。到达间隔与速率是 PC 观测，不是精密时钟测量。UDP 不含 PHY/PLL/ARP 遥测；SYS3 单独连接后按域新鲜度显示相关回读，未连接或过期不能当作当前健康状态。温度、电压、外部负载和声学性能仍需外部验证。

诊断 JSON 的 `hardware_reference` 保持 `reference_only=true`、`detected_firmware=null`；串口实现后 `uart_supported_by_host=true`，不等于已经连接。窗口导出的诊断增加 `sys3_uart`：连接/时效、域新鲜标记、计数、命令状态、原始字及有界日志。通道包含 `connector`、`io_bank`、`fpga_pad`；旧 `clock_group` 为 `null`。首次无数据时界面不把默认零值或负时间作为有效观测。

诊断字段`receiver_failed`单独标识接收器绑定失败；`error`保留最近接收异常文本。曾出现格式错误后手动停止，不会被误称为接收器故障。

前处理状态 bit0..3 和 bit5 是故障；bit4 是模式而不是故障；bit5 必须与 bit4 同时出现；未知保留位直接拒绝。前处理故障按主机会话锁存，本版采用保守策略：任一质量故障使该会话停止声学处理。UI 的通道削顶计数与 FPGA 的“曾饱和”锁存位含义不同。

### 自测验收

参考表 `16×128×3=6144` 字节，按 `frame_id % 16` 和通道索引比较。参考 SHA-256：

`fb653a4b25043495c2f54b36fbe9df7a9d9d6df06cbb95ce1d888bec444dc75e`

至少 48,000 个自测帧、数值全部一致、无错误标志、无观察范围内不连续、无已知主机队列/格式丢弃才显示 PASS。发生错误后本次审计不因后续正常包自动恢复，重新接收或进入新 epoch 建立新审计。通过只证明当前观察范围内 PC 数字链路；LED4 故障、外部接线和真实声学性能仍需板级/现场判断。

### 连续性与有界资源

网络接收独立线程，申请 8 MiB socket 缓冲，按数据报边界接收；网络到处理线程队列最多 8192 包，溢出显式计数。UI 每 100 ms 拉取最新状态，不为每个包投递 UI 事件。写盘另用专用线程，64 MiB / 4096 块双上限，溢出停止录制并保存错误信息。128 轨 PCM 批量写入，避免每个通道样本独立磁盘调用。

包号/帧号用模 2^64 序号和已接收区间跟踪；中途开始不会把接收前的数据算作丢失。`missing_observed_range` 会随乱序补齐下降；`forward_gap_observations` 是累计跳号观察量，不是最终丢失数。区间超过 65536 个后明确标记 `exact=false`，不假装计数精确。

改变 epoch/自测模式、停流超过 1.5 秒后恢复、重新点击接收，建立新的主机运行标识；旧 epoch 的迟到包保留为证据但不送入声学处理。丢帧、重复、乱序、配置切换均切断声学窗口并使在途定位结果失效。协议不能无歧义识别“没有明显停流且 epoch 被重用”的硬复位，遇到重烧录/复位应手动重新接收。

## 定位、校准与降噪

硬件保证的有效通带为 20 Hz–16 kHz，DC 保留；16–24 kHz 不能当作保证的定位带宽。主机 SRP 默认分析频带约 250–8000 Hz 是软件选频，不是硬件规格；频谱图展示到 Nyquist 24 kHz 不代表全频段都在通带内。

必须导入真实机械/布线表坐标。JSON 格式如下，必须包含完整 128 项，不能用这个示意片段进行定位：

```json
{"format":"micarray128-geometry-v1","name":"机械表版本","units":"m",
 "microphones":[{"channel":0,"x":0.012,"y":0.034,"z":0.0}]}
```

代码检查完整通道数、唯一索引、有限数值、±2 米范围、重复位置和共线退化。+X 向右、+Y 向上、+Z 向前，方位右正、俯仰上正。平面阵列仍不能物理区分前后镜像。

**2026-09-21 方向修正**：方向指向声源，而不是波传播方向；靠近声源的阵元更早收到声音。独立球面传播距离测试发现旧定位与软件波束的时延符号相反，现已同步修正。曾用旧版做过视频方向校准或方向测试的现场，需要重新核对 +X/+Y、通道布线和视角关系；软件不会覆盖已有坐标或校准设置。

128 定位器独立实现 2048 点、约 250..8000 Hz 的 SRP-PHAT：128 通道频谱、最多 256 条覆盖全通道的基线、相对能量质量门控、窄带拒绝、真实坐标转向、网格与连续局部搜索。最多每 100 ms 提交最新窗口，定位线程只保留一个等待窗口。默认网格 72×45，可设 24..160 × 15..100；不宣称继承旧 48 阵列的精度/640×360性能或神经模型指标。可信阈值默认 0.35，可调 0..1；低可信候选仅冷色弱显示，热力聚焦 0.5..4 仅改变颜色映射。

数值定位增加独立于像素网格的前半球3°角度搜索及连续精化，解决170°宽视场/粗网格中心采样不足。画面外更强主峰会明确提示“主峰位于视频视场外”，不会挤压成边缘可信标记；阈值0不能绕过视场保护。热力图在每个显示单元保留真实计算的子像素响应最大值，不叠加人工圆斑。128版使用独立2048点不可变FFT计划缓存，逐点对照原FFT和逆变换验证，不修改旧48版FFT。

右侧“实时定位 / 视角校准”页签包含五个针孔参数及四点常显表格；需至少四次稳定可信方向才允许采点，过近/波动过大、流过期、结果过期或代次不匹配时拒绝采点。采集进度显示0/4，未采点时撤销禁用，满四点后才开放拟合。支持隐藏点和校准文件导入导出；新版`m128-camera-v2`保存五参数、四点样本及质量值、参考图像尺寸和`pinhole`投影标识，仍可载入旧v1文件。严格校验且失败不修改现有设置，导出采用检查写入长度的原子替换；参考宽高比与当前图像不符时提示核对。定位和降噪复用同一 USB 视角，不混入旧广角模型。

降噪用真实 128 阵元位置和连续角度生成 A/B1/B2：四点三次 Lagrange 分数延时、共享因果参考延时；随后固定/自适应维纳、单/双抑制参考、带通/LogMMSE/AGC 后处理。拖动过程中连续更新角度并保留波束/滤波历史，不因细微角度调整反复清空监听缓冲；松开时保存设置。后处理可重排并独立旁路。监听可选原始 CH0..127 或波束/各阶段，增益 −60..+48 dB，预缓冲 50..1000 ms（默认250），独立有界 FIFO。

直接拖动任一标记会同步选中对应A/B1/B2，点击空白移动当前目标；方向键微调0.1°，Shift+方向键为1°。后处理列表显示启用/旁路状态，支持拖动或Alt+↑/↓调序，维纳仍固定在首位。输出设备变更、启动或写入失败会停止监听并提示；采集和录制不受影响。

## 音频录制

录制来源为原始阵列任选通道，或维纳/带通/LogMMSE/AGC 后节点。默认每轨独立单声道 PCM24 WAV，可直接播放器播放；也支持一个多通道 WAV（>2 通道使用 WAVE_FORMAT_EXTENSIBLE，无虚构扬声器布局）。原始 PCM 不受监听增益影响。每次唯一新目录，文件以 NewOnly 创建，不覆盖既有录音。

任何帧号缺口/重复/乱序、主机会话或模式改变使原始 WAV 分段，保留到达顺序但不会把缺帧补零后说成连续音频。录制器独立检查相邻帧号和 epoch，旧 epoch 迟到包及其后的当前会话包不会混写；原始音轨各分段记录 epoch。DSP 使用独立连续性编号，清单记输入边界和输出样本数；算法存在自身延迟，不能把后处理轨道宣称为原始样本时间戳。单文件数据达到 256 MiB 自动新分段。

`packets.m128` 格式：8字节 ASCII `M128CAP1`，随后固定 1224 字节记录：u64be 主机单调到达纳秒、u64be 主机运行编号、1208 字节原始合法 UDP 负载。不保存被来源过滤或格式拒绝的数据报；这些计数见诊断报告。`manifest.json` 保存配置、轨道、分段、自测/质量标签、计数和完成状态；未正常结束可能仍为 `complete=false`。录制证据和清单请一起保留。

清单同时保存开始与结束时的流诊断，需对比接收队列丢弃和格式错误计数；`complete=true` 表示文件正常写完，不等价于硬件或采样连续性验收通过。

录制中关闭窗口会询问是否停止并完成写盘，可取消退出；确认后锁定操作、等待录制线程完成文件和清单，再退出。写盘失败时保留窗口和错误提示，避免静默丢失证据。后台录制错误会显示全局常显告警，不必停留在录制页才能看到。

录制文件可在外部音频软件中使用；本程序不再提供 WAV 文件回放或文件定位分析。`packets.m128` 的独立诊断检查工具保留，用于数字链路取证。

## 命令行联调

```powershell
python array128/tools/m128_tool.py probe --seconds 5 --output build-array128/evidence/new-run.json
python array128/tools/m128_tool.py simulate --destination 127.0.0.1 --source-port 5001 --seconds 10
python array128/tools/m128_tool.py inspect path/to/packets.m128
python -m unittest discover -s array128/tools -p "test_*.py" -v
```

模拟时上位机只接收来源设 `127.0.0.1:5001`。模拟器发送官方自测数据，不模拟声学阵元几何；`--drop-every` 可注入丢包。探针和上位机不要同时占用相同监听端口。

```powershell
.\build-array128\MicArray128.exe --diagnose-seconds 8 --report build-array128/evidence/new-qt-run.json
```

此命令会真实开始接收，到时先停止接收并刷新最终审计，再导出报告和退出，不向硬件发送任何命令。

可追加 `--capture-array build-array128/evidence/captures` 同时录制 128 个独立 PCM24 音轨和 UDP 证据；每次创建唯一子目录，不改录制页面的保存参数。必须配合 `--diagnose-seconds` 限定时长，退出时等待已接收的录制队列写盘。诊断快照与最终 `manifest.json` 一起检查，尤其关注主机丢弃计数。

调试总览和 JSON 分别报告来源数据报最近到达时间、最近合法包处理延迟和主机队列深度，便于区分源端停流与主机处理积压。来源到达时间仅涵盖来源与 1208 字节长度匹配的数据报，不等价于协议和自测校验通过；时间值 −1 表示尚无对应观测。

### Windows 防火墙

程序不会自行修改防火墙。经明确批准后，可用管理员 PowerShell 执行 `array128/tools/allow_fpga_firewall.ps1`：它只允许 `D:\Workspace\QT\MicArray\build-array128\MicArray128.exe` 接收来自 `192.168.10.2:5000` 的 UDP、本机端口 5000，不关闭防火墙，也不修改其他规则。脚本不放行独立发布目录中的另一可执行路径。Windows 的 UAC 管理员确认与聊天中的批准是两个不同步骤。

# PL 三路波束与上位机原降噪

本分支增加真实 PL A/B1/B2 三路浮点波束输入。维纳抑制、带通、LogMMSE、AGC 仍使用原 GitHub 源码，在上位机执行一次。没有将全部降噪运算移入 PL，不增加声纹功能。

## 模式与操作

- **48 通道软件波束形成（CH0–CH47）**：保留原完整软件链，作为演示基准与用户明确选择的回退方式。
- **PL 三路波束 + 上位机原降噪（AUD3/DNS1）**：只接收配套 bit 输出的三路 float32 波束，不执行软件波束形成。没有收到合法三路波束时等待或报错，不把原始 CH1/CH2/CH3 当作波束，也不自动切回软件。
- **旧设备兼容：预先波束形成的 CH1/CH2/CH3**：仅用于确实预先输出该语义的旧设备，与新 PL 三路浮点协议分开。

连接配套设备、启用降噪并进入降噪页，解锁方向控制后选择新 PL 模式。首次进入、重连或点击“重新同步PL方向”时，软件发送 RESET，逐项确认后发送 BEGIN、六个 Q26 斜率和 COMMIT。状态显示配置已就绪后，三路波束才交给原降噪链。网络写成功不等于设备已执行。

正常调整 A/B1/B2 方向只提交新系数，不发送 RESET，也不清除波束或上位机 DSP 历史。后处理参数、顺序或输入模式发生变化时，仍执行原程序规定的复位行为。

保持原演示中的算法、单点/两点模式、抑制系数、带通、LogMMSE FFT/重叠/平滑、AGC、节点顺序和监听增益。特别是本机保存的演示使用 LogMMSE 2048 点，不能用默认 512 点代替。监听增益作用于最终 PCM16 播放，独立于 AGC；不为了让频谱更干净而改变增益或静音目标。

CH0 仍是原始参考，可独立显示或监听，不属于降噪输出。原始低 24 位的 48 通道及通道次序保持原样。相机与定位页继承复制工程原有的镜头参数支持。

本程序使用自己的便携 INI 设置目录与 `MicArrayPLDenoiseTrial` 配置名，初次运行仅从旧配置读取一次，不改原运行版本注册表。建议关闭旧程序的扬声器监听，避免多个程序回放或 TCP 设备占用。

## 数据与故障处理

AUD3 位于 CH7–CH47 的高字节，每包含 1 或 2 个同步 A/B1/B2 float32 tuple。接收端检查 CRC8、版本/阶段/格式、保留位、配置 id、样本序号和浮点有限性。DNS1 提供活动配置、ACK、ready/busy、溢出、错误和 build id。接收端按实际样本序号重组 200 点；配置切换处不足 200 点的旧尾部以真实短帧送入后续链，不删除或补零。

新配置音频先于 COMMIT ACK 到达时，最多缓冲 96000 个同步样本，确认后按原顺序释放；不会因为 ACK 延迟而删除新 epoch 前段。配置期间的控制 CRC error=1 是分字写入可能出现的暂态状态，保留诊断并使用相同事务、相同字段重发。音频 CRC、缺样/重复、过期或交错配置、非有限浮点、真实溢出、其他设备错误和超时均锁住 PL 输出并显示原因。恢复使用明确的“重新同步PL方向”，不隐藏降级。

初始 RESET、BEGIN、六字段、COMMIT 共 9 个有确认的命令；普通方向变更共 8 个。每条命令使用已有 26 字节控制帧，六个 int16 携带 magic、事务、字段、32 位值和 CRC16，后两个保留值为零。超时 150 ms 重发，最多 8 次重发。COMMIT 必须收到活动配置 id 与事务一致且 ready 的确认。

## 验证与证据边界

`test_pldenoise` 验证 CRC 标准向量、Q26 连续方向斜率、逐项 ACK/重发、真正应用后的 COMMIT、方向变更不复位、音频异常拒绝、新 epoch 提前到达、原始 48 路不变和软件后缀等价。localhost TCP mock 使用实际 DeviceClient/ProtocolCodec，故意丢失一个 ACK 后重发，并把原黄金三路浮点样本通过 AUD3 送到实际 Worker，比较四级完整软件输出。

`test_pldenoise_ui` 验证页面选项/状态、缺流不伪造波束、实际 GUI 到工作线程握手，以及方向变更保留 DSP 历史。`test_cameralens` 和已有定位/热力图测试保留。旧融合截图断言只按实际 devicePixelRatio 将逻辑投影位置换算成物理图像像素，未修改相机和定位代码。

`pl_denoise_replay` 读取三路 `.f32le`，调用实际 Worker 的新入口，保留完整输出批次；不补尾、不刷零、不裁暖启动、不拟合增益。`tools/evaluate_fixed_suffix.py` 将四组定点模型三波束送入原软件后缀，与原 GitHub 黄金结果逐级比较样本数、最大绝对误差、误差 SNR、RMS 电平差和非有限数。数值门槛为本项目内部实现约束，不宣称行业音质标准。

浮点软件等价、固定模型数值误差、RTL 一致性、时序/资源报告、bit 文件和真实板上听感验收分别报告。离线软件通过不能代替上板声音、实际通道方向、丢包、端到端时延和目标保真度验证。
